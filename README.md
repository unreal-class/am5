# AM5 테니스 경기 관리

AM5 동호회의 출석, 복식 대진표 자동 생성, 경기 시작/종료/결과 입력, 개인 전적, 월간/연간/전체 랭킹을 관리하는 **모바일 우선 웹 서비스**입니다.

## 기술 구성

- **Next.js** (App Router, TypeScript)
- **Supabase** (Auth + PostgreSQL, RLS)
- **Vercel** 배포

## 주요 기능

- 회원가입 / 로그인 (초기 비밀번호 `AM5AM5`, 첫 로그인 시 변경 강제)
- 출석 / 퇴장 (당일 모임 자동 생성)
- 출석자 + 가용 코트 기준 **복식 대진 자동 생성**
- 경기 시작 / 종료 기록, 점수 입력, 승패 저장
- 개인 승 / 패 / 승률 및 **월간 / 연간 / 전체 랭킹**
- **관리자 전용**
  - 회원 조회, 수정, 권한 부여, 비밀번호 초기화, 삭제
  - 가용 코트 대여 시작 / 종료
  - 경기 기록 삭제 (개별 / 일괄)
  - 테스트 콘솔

## 경기 배정 규칙

### 배정 대상
- 오늘 모임에 출석 중이고 퇴장하지 않은 회원
- 현재 진행 중 / 예정된 경기가 없는 회원
- 가용 코트가 있고 대기 인원 4명 이상일 때 배정
- 재입장 시 현재 출석 기록의 시간으로 대기 순서를 계산하며, 이전 퇴장 시간이나 다른 모임의 출석 기록은 사용하지 않습니다. 당일 경기 횟수는 유지됩니다.

### 배정 우선순위
배정 가능한 선수 중 한 명이라도 오늘 경기 수가 3경기 미만이면 아래 순서를 기본 원칙으로 사용합니다.

| 순위 | 기준 | 방향 |
|------|------|------|
| 1 | 오늘 경기 횟수 | 적은 사람 우선 |
| 2 | 대기 시간 (출석 후 경과) | 긴 사람 우선 |
| 3 | 출석 시간 | 빠른 사람 우선 |

배정 가능한 모든 선수의 오늘 경기 수가 3경기 이상이면 경기 수와 대기시간 대신 출석 시간이 빠른 상위 4명을 우선 배정합니다.

### 팀 분배 우선순위
선정된 4명을 A팀 / B팀으로 나눌 때 아래 순서로 최적 조합을 찾습니다.

| 순위 | 기준 | 설명 |
|------|------|------|
| 1 | 남녀 혼성 | 여성 인원이 있으면 각 팀이 남성+여성 조합 |
| 2 | 동일 대진 회피 | 두 팀의 구성이 같은 대진의 누적 횟수가 적은 조합 우선 (A/B 교환도 동일 대진) |
| 3 | 파트너 중복 회피 | 같은 팀 경험 조합 최대한 회피 |
| 4 | 승률 균형 | 위 조건이 같으면 A팀과 B팀 평균 승률 차이 최소화 |

선정된 4명과 혼성 조건상 가능한 조합을 모두 사용한 경우에는 반복 횟수가 적은 대진부터 재사용합니다. 전원 3경기 이상일 때의 출석 순서 규칙에 따라 같은 4명이 다시 선정될 수 있습니다.

### 생성 수
`min(가용 코트 수, ⌊대기 인원 ÷ 4⌋)` 만큼의 경기가 한 번에 생성됩니다.

### 경기 중 퇴장과 충원
- 경기 중 또는 예정된 경기의 참여자가 퇴장하면 해당 자리만 비웁니다. 나머지 참여자와 팀, 경기 ID, 코트, 시작 시간은 유지합니다.
- 대체 선수는 출석 중이며 예정/진행 중인 경기가 없는 회원 중에서 선정합니다. 후보 중 3경기 미만이 있으면 당일 경기 수 → 대기시간 → 최근 입장 시간 순, 전원이 3경기 이상이면 입장 시간 순입니다. 동률이면 고정된 팀을 기준으로 혼성 → 동일 대진 회피 → 파트너 중복 회피 → 승률 균형을 적용합니다.
- 후보가 없으면 퇴장은 완료하고 기존 참여자를 유지한 채 **충원 대기**합니다. 반복 퇴장으로 빈자리가 여러 개 생겨도 같은 방식으로 처리합니다.
- 출석·경기 결과 저장·관리자 배정 등 자동 배정 실행 시 기존 경기의 빈자리부터 채운 다음 새 경기를 만듭니다. 충원 대기 중인 참여자와 코트는 다른 경기에 배정되지 않습니다.
- 종료되어 결과 입력만 남은 경기의 참여자는 퇴장해도 유지합니다. 충원 대기 중인 경기는 종료/결과 입력을 할 수 없습니다.

### 참여자 팀 재구성
- 참여자 4명이 모두 배정된 예정/진행 중 경기에서는 해당 경기 참여자 또는 관리자가 `팀 재구성`을 누를 수 있습니다.
- 버튼을 누를 때마다 같은 4명으로 만들 수 있는 3개의 복식 팀 조합을 차례로 순환합니다. 원하는 조합이 표시되면 더 누르지 않고 그대로 경기를 진행하면 됩니다.
- 참여 인원, 경기 ID, 코트와 시작 시간은 바뀌지 않습니다. 충원 대기, 종료 또는 결과가 입력된 경기는 재구성할 수 없습니다.

### 관리자 경기 운영
- `재배정 실행`: 현재 경기는 유지하고 충원 대기 자리와 경기 중이 아닌 출석자를 다시 배정합니다.
- `전체 중단 후 재배정`: 예정·진행 중인 경기를 삭제하고 현재 출석자와 가용 코트 기준으로 새 대진을 만듭니다. 완료된 결과는 유지합니다.
- `모임 종료 및 전원 퇴장`: 예정·진행 중인 경기를 중단하고 출석 중인 모든 참여자를 퇴장 처리한 뒤 모임을 종료합니다. 완료된 결과는 유지합니다.
- 전체 중단과 모임 종료는 실행 전 확인창을 표시합니다. 경기 중단, 전원 퇴장 및 모임 종료 상태 변경은 DB에서 원자적으로 처리합니다. 전체 중단 뒤 새 대진 생성에 실패하면 중단 상태를 명확히 안내하고 일반 재배정으로 다시 시도할 수 있습니다.

### 업데이트 적용 및 검증
기존 DB에는 앱 배포 전에 `supabase/migrations`의 `202609270001`, `202609270002`, `202609270003` SQL을 번호 순서대로 적용해야 합니다. 앞선 파일을 이미 적용했다면 이후 파일만 추가로 실행합니다. 신규 설치용 `supabase/schema.sql`에도 동일한 함수와 트리거가 포함되어 있습니다.

`npm test`로 배정 회귀 테스트와 PostgreSQL(PGlite) 기반 퇴장·충원 통합 테스트를 실행합니다. 테스트에는 Node.js 22.15 이상 또는 24 이상이 필요합니다. `npm run typecheck`, `npm run build`로 앱 검증을 실행합니다.

```sql
update public.profiles set role = 'admin' where login_id = '회원이름';
```
